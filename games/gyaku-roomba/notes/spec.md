# 逆ルンバ VS ルンバ — ゲーム仕様・議論まとめ

- 文書種別：企画・実装引き継ぎ資料
- 対象：HTMLプロトタイプ v2（`index.html`、元ファイル名 `gyaku_roomba_vs_roomba_v2.html`）
- 更新日：2026-10-15
- 状態：1対1のCPU対戦プロトタイプ実装済み。ゲームバランス・演出は検証段階。

> **ゲームの核：猫は毛を撒く。ルンバは毛を吸い取る。** ルンバが床を色で塗ったり、新しい汚れを作ったりしてはいけない。双方が同じ塗り合いをするのではなく、「汚す vs 掃除する」という非対称な陣取り対戦にする。

## 1. 発端と企画の方向性

### 元ネタ

実際の飼い猫が毛玉を家じゅうにまき散らすため、「逆ルンバ」と呼ばれていることが発端。掃除機は汚れを取り除くが、逆ルンバは汚れを生産・拡散する。この日常の観察を、馬鹿馬鹿しくも直感的に遊べるゲームにしたい。

### 初期のアイデア出し

「逆ルンバ」という題材から、以下のような幅広いゲーム案を検討した。

1. **逆ルンバ.io**：猫が毛を撒き、家から街・地球へ汚染規模を広げる。
2. **逆ルンバ VS ルンバ**：猫の散毛とルンバの掃除がぶつかる陣取り対戦。
3. **出勤妨害ねこ**：飼い主が出勤する前に服などへ毛を付けるスコアアタック。
4. **毛玉インフレーション**：毛の生産量を指数関数的に増やす放置ゲーム。
5. **毛玉スナイパー**：吐き出した毛玉を狙った場所へ飛ばす物理パズル。
6. **逆ルンバ・タワーディフェンス**：掃除用具と毛玉を生産する猫の対決。
7. **毛玉雪だるま**：散らばった毛を巻き込んで巨大化する。
8. **完全犯罪ねこ**：飼い主が帰る前に汚し、何食わぬ顔で寝るステルスゲーム。
9. **ねこ毛感染シミュレーター**：飼い主や空調を通して毛が世界中に拡散。
10. **換毛期シューティング**：毛の全方位攻撃で掃除用具に抗うサバイバル系。
11. **毛玉エンジニア**：猫毛から機械や設備をクラフトする。
12. **汚部屋経営シミュレーター**：猫を雇って施設を汚染する逆経営ゲーム。

この中から、ユーザーが**「スプラトゥーンみたいな感じで、ルンバ VS 逆ルンバ」**を指定し、陣地争いの方向に確定した。

## 2. 決定済みコンセプト

| 項目 | 方針 |
|---|---|
| 仮タイトル | **逆ルンバ VS ルンバ** |
| ジャンル | トップダウン型・非対称陣取りアクション |
| 着想元 | 『スプラトゥーン』の「フィールド占有率で勝敗が決まる」気持ちよさ |
| 対戦構造 | 猫（汚す側） vs ルンバ（掃除する側） |
| 基本的な楽しさ | 床の状態がみるみる変化する視覚的フィードバック、攻防と取り返し |
| 1試合 | 90秒（現行プロトタイプ値） |
| 現状のプレイ人数 | 人間1人 vs CPU1体 |
| 実行方式 | 単一HTMLをブラウザで開く。外部サーバー不要 |

**重要な非対称性：**

- 猫は床に**新たな毛**を発生させて占有率を増やせる。
- ルンバは**既に存在する毛のみ**除去できる。何もない床を掃除しても色や汚れは増えない。
- 地面の状態は原則として「元のきれいな床」「猫毛」の2種類。家具などの障害物は計測対象から除外。
- ルンバが掃除した場所は**元の床**に戻る。ルンバ色の陣地を作るのではない。

## 3. これまでの実装・修正履歴

### v1：最初のHTML試作

- 猫／ルンバを選択してCPUと1対1で対戦。
- WASD移動、マウス照準、左クリック長押し攻撃、Space必殺技。
- 90秒の占有率対決、家具の障害物、停止・リスタートを実装。
- **問題点：ルンバも床を水色に塗り、結果として部屋を「汚している」ように見えた。** ルンバの役割が猫と対称的な塗り合いになっていた。

### ユーザーからの重要フィードバック

> 「ルンバも部屋を汚しているので、ルンバは猫の毛を吸い取ることだけに注力してほしい」

これは単なる色の変更ではなく、**プレイヤーの役割・行動・勝敗の定義に関わる仕様変更**として扱う。

### v2：現在の最新版

- ルンバの水色ペイントを廃止。
- 猫毛はオレンジ系のタイルとして残る。
- ルンバが通ると、その場所の**毛があるタイルだけ**が元の床に戻る。
- ルンバのクリック長押し攻撃は、水色弾ではなく**前方扇形の吸引**。
- ルンバAIは毛が多い場所を探し、近い毛を狙って掃除する。
- 勝敗は「猫毛の床 vs きれいな床」の比率に変更。
- ルンバのUIは水色を使うが、**ゲームフィールドを水色に塗らない**。

以後、**v2のルールを正**とし、v1の塗り合い表現には戻さない。

## 4. 現行のプレイルール（v2）

### 試合の流れ

1. タイトル画面で「逆ルンバ（猫）」または「ルンバ」を選ぶ。
2. 90秒の1対1対戦が開始。選ばなかった側をCPUが操作。
3. 猫は動き回り、毛玉を撃って床を汚す。
4. ルンバは汚れた場所に移動し、通過時・吸引時に猫毛を取り除く。
5. 画面上部に猫毛と清潔な床の割合がリアルタイム表示される。
6. 残り時間0秒で占有率を比較し、勝敗結果を表示。再戦可能。

### 勝敗

- **猫の勝利：** 終了時点で、計測対象の床面積の**50%超**が猫毛。
- **ルンバの勝利：** 終了時点で、計測対象の床面積の**50%超**がきれいな床。
- **引き分け：** ちょうど50%ずつ。
- **注意：** 初期状態の床はすべて清潔であり、最初からルンバ側のスコアとして扱われる。ルンバは自分の色を追加しなくても、毛のない床によって勝てる。

### 猫（逆ルンバ）

| アクション | 動作 |
|---|---|
| 自動散毛 | 足元付近に継続的に毛を付着させる。既に毛がある床を重ね塗りしても面積は増えない。 |
| 毛玉射撃 | マウス方向に毛玉を発射。壁・家具・相手への衝突や寿命終了で着弾、周囲に毛を散らす。 |
| 必殺技 | **換毛期バースト**：自分の周囲に大量の毛を撒く。 |
| 妨害 | 毛玉の爆発が相手に当たると、一時的にスタンさせ、軽く押し出す。 |

### ルンバ

| アクション | 動作 |
|---|---|
| 自動清掃 | 自分の足元にある猫毛を取り除く。毛がない部分には何もしない。 |
| 吸引 | マウス方向に扇形の吸引エリアを出し、そこに落ちている毛だけを除去する。通常の吸引は家具の裏側まで届かないように判定する。 |
| 必殺技 | **超強力おそうじ**：自分の周囲の猫毛を広範囲に除去する。 |
| 陣地 | 新しい色や汚れは一切生成せず、既存の清潔な床を維持・回復する。 |

### 必殺技

- 猫／ルンバとも、現行コードでは使用後**10秒のクールダウン**。
- プレイヤーはSpaceキーで発動。
- 必殺技の準備状況はゲージで表示。
- **現行CPUのAIは必殺技を使わない**（対戦調整上の未実装・改善余地）。

### 操作

| アクション | PC |
|---|---|
| 移動 | `WASD` または矢印キー |
| 狙う | マウス移動 |
| 射撃／吸引 | 左クリック長押し |
| 必殺技 | `Space` |
| 一時停止／再開 | `P`（または一部状態で`Escape`） |
| 最初から | 画面上部の「やり直す」 |
| サウンド | 画面上部でON/OFF（初期設定OFF） |

タッチ端末向けには仮想スティック、攻撃ボタン、必殺技ボタンも実装されている。ただし、PCと同じ照準・操作感を保証するものではなく検証が必要。

- ソファ、テーブル、棚、ラグ、デスク、観葉植物などを家具・障害物として配置。
- 家具は移動を遮り、一部の攻撃／吸引も遮る。

### UI

- 中央：対戦ステージ、プレイヤー／CPU、毛玉と吸引の演出。
- 下：操作案内、必殺技名、クールダウンゲージ、簡易ルール。

## 6. 実装概要（HTML v2のコード準拠）

| パラメータ | 現行値・方式 |
|---|---|
| 描画 | HTML Canvas 2D + JavaScript + CSS |
| ゲームフィールド | 論理座標 **1100 × 620 px** |
| タイル | **10 × 10 px** 単位で床の状態を管理（110 × 62） |
| タイル状態 | `0`: 清潔、`1`: 猫毛、`3`: 家具・障害物 |
| 面積算出 | 家具を除く床タイルに対する毛タイル／清潔タイル数の比率 |
| 猫の移動速度 | **218 px/s**（基本値） |
| ルンバの移動速度 | **204 px/s**（基本値） |
| 猫の足元散毛半径 | **33 px** |
| ルンバの足元清掃半径 | **37 px** |
| 猫の毛玉 | 速度 **600 px/s**、着弾時の散毛半径 **51 px** |
| 猫の射撃間隔 | 人間操作時 **0.24秒**／CPU時 **0.58秒** |
| ルンバの通常吸引 | 前方約 **178 px**、半角約 **0.51 rad** の扇形 |
| 吸引の更新間隔 | 約 **0.075秒** |
| 猫の必殺技範囲 | 半径 **132 px** |
| ルンバの必殺技範囲 | 半径 **140 px** |
| 必殺技クールダウン | **10秒** |
| 対戦時間 | **90秒** |

技術的なポイント：

- 床タイルの状態を `Uint8Array` に保持。猫毛の見た目は別Canvasレイヤーに描き、清掃時には該当領域をクリアする。
- `paint(x, y, r, team)` が床の状態変更を担当。**猫は `0 → 1` のみ、ルンバは `1 → 0` のみ**。
- `vacuumCone(actor)` はルンバの扇形吸引。猫毛タイルのみを対象とし、簡易的な遮蔽物チェックを行う。
- ルンバAIは `nearbyFur`／`nearestFur` などを使って毛のある場所を優先する。
- 猫AIは未汚染領域を優先し、毛玉攻撃を使う。
- 画面は `requestAnimationFrame` で更新。状態はJavaScriptメモリ内で管理し、サーバー通信や永続保存はない。

## 7. この企画で守りたい設計原則

1. **キャラクターの役割が直感的であること。** 猫＝汚す、ルンバ＝掃除する、を説明不要のレベルまで徹底する。
2. **掃除は「ペイント」ではない。** ルンバが通った床を水色に着色する仕様は禁止。UIのチームカラーとしての水色利用は可能。
3. **床の変化そのものが報酬になること。** 毛の広がり／吸い取られる気持ちよさを最優先する。
4. **片側が単なる劣化コピーにならないこと。** 猫は面積を作り、ルンバは毛の密集を見つけて効率よく取り除く、異なる判断を要求する。
5. **くだらない題材と遊びの手応えを両立すること。** 猫の理不尽さ、悪びれない表情、毛玉災害の誇張は演出の方向性として有望。

## 8. 現時点で未実装・未検証の要素

以下は**合意済み仕様ではなく、今後検討すべき課題・提案**。

### 優先度：高

- **対戦バランス**：開始時点で清潔な床が100%なので、ルンバ側が初期優位。猫が90秒で50%を超えられるか、陣営ごとの勝率検証が必要。
- **ルンバ固有の楽しさ**：掃除の手応え、吸引の視認性、まとめて回収した際の爽快感を高める。単なる色消しに留めない。
- **AI強化**：猫は散毛効率、ルンバは毛の集中箇所や移動コスト、家具の回り込みをより良く判断。CPU必殺技の使用も検討。
- **局所的な戦術**：毛を密集させる／広く薄く散らす、効率的な掃除経路を取る、家具で吸引を防ぐなどの意思決定を明確にする。

### 優先度：中

- **毛玉の物理表現**：飛び散る、転がる、まとまる、吸い込まれる挙動を視覚的に強化する。
- **猫の固有演出**：しっぽ、毛づくろい、悪びれない勝利・敗北演出、個性ある猫のアニメーション。
- **ステージバリエーション**：狭い廊下、家具の多いリビング、衣類に付着しやすい部屋など。
- **対人戦**：ローカル2人／オンライン対戦などは未実装。必要性が確認できてから通信方式を選定。
- **ゲームループ拡張**：リザルト、称号、リプレイ性、短期成長要素などを検討。

### 特に未決定の問い

- 猫毛が50%を超えたら勝ち、という単純ルールを維持するか。
- ルンバの吸引範囲と移動性能は、猫の散毛量に対して適正か。
- 猫が撃った毛玉でルンバを妨害する要素をどの程度強くするか。
- 毛の「密度」をゲーム要素にするか、現状の二値タイルで留めるか。
- スプラトゥーン的な見やすさと、本物の猫毛らしいふわふわ感をどう両立するか。

## 9. 次の開発者・AIエージェント向け指示

**ベースにするファイル：** `gyaku_roomba_vs_roomba_v2.html`

改良時は以下を必ず守る。

1. まずv2の「猫毛生成／猫毛除去のみ」という非対称ルールを保持する。
2. **ルンバが水色の跡を残さないこと**、何もない床への吸引が陣地率を変えないことを確認する。
3. 猫毛が追加された場合は猫%が増え、ルンバが吸い取った場合は猫%が減って清潔%が増えることを確認する。
4. 家具部分の面積が陣地率に含まれないことを確認する。
5. 対戦開始、攻撃、必殺技、90秒後の終了、再戦が正常に動くことを確認する。
6. 将来の演出・新ルールの提案を、**既に決定した仕様**と混同しない。
